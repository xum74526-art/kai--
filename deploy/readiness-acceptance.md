# 可靠性验收记录

> 旧版部署参考：本目录内容从 KAI影原 main 保留，尚未适配上游 v1.6.6，尤其 `/kai/` 子路径、登录 Cookie、资源地址和镜像启动流程。不要直接按本文命令更新线上环境。当前升级范围仅为本地 SQLite 数据库及其测试；线上部署须另行适配并完成验证。

## 本轮范围

本轮只补可靠性与发布保护，不重新设计页面，不调整注册政策、不迁移数据库、不改模型价格或现有生成协议。没有执行推送、云端部署、真实模型收费调用或正式数据恢复。

| 范围 | 实现 |
| --- | --- |
| 创作任务 | 抽离可独立测试的任务结果归并逻辑，修复类型推断导致的生产构建失败；覆盖批量部分失败、成功结果保留、取消和旧回调 |
| 登录与账号 | 登录服务故障不再当游客处理；停用用户、撤销会话和审计同事务成功/回滚 |
| 错误定位 | 后端自行生成 32 位十六进制请求编号，失败响应和日志关联；前端只接受严格格式，不反射客户端自定义内容 |
| 生命周期 | 区分进程存活与服务就绪；关闭实例时停止领取、排空任务，保留持久化任务恢复语义 |
| 发布 | 前端测试和生产构建进入质量关卡；前后端候选版本都成功后才提供同 revision 的发布组合 |
| 数据保护 | 备份包含数据库、本地媒体与 `.settings-key`；校验与恢复演练在隔离环境完成 |
| 未完成功能 | 超分明确暂未开放；图片放大/查看保持可用；录音测试入口只存在于开发构建 |

## 本地验证

验证使用自动化测试的合成账号、临时数据库及测试媒体，没有对真实用户数据库做故障注入：

- `backend: go test ./...`、`go vet ./...`：通过；覆盖登录故障、用户停用事务、请求编号、就绪探针、任务停机边界和上游任务恢复。
- `web: bun run test`：461 项通过、0 项失败；`bun run build`：生产构建通过。Vite 仍提示部分 chunk 超过 500 KB，该提示不影响本轮正确性验证。
- `canvas-agent: bun run build`：通过。完整测试在当前 Windows 受限环境中运行到进程清理用例时，因系统拒绝进程检查/终止权限而无法作为有效结论；Linux CI 会继续把完整测试作为发布硬门槛。
- 四组 Compose 配置执行 `docker compose ... config --quiet`：均通过；仅出现当前机器无法读取 Docker 用户配置的权限警告，不影响配置解析。
- 发布工作流 YAML 解析、四个部署脚本 `bash -n`、`git diff --check`：通过。
- SQLite 合成数据执行“静默备份 → 校验和 → 隔离恢复 → 数据库完整性检查”：通过；带 `..` 越界成员的恶意归档被恢复脚本拒绝。

## 上线前仍须确认

以下项目没有因为单元测试通过而自动完成，需要部署负责人配合验证：

1. 实际服务器的 HTTPS、反向代理、Cookie、可信代理/CORS 配置、数据目录权限与备份权限。
2. 普通用户登录、管理员权限隔离、用户切换和真实任务访问归属。
3. 文本 SSE 断线续传，以及当前有权限的图片/视频模型各一次最低规格真实调用；这会产生费用，须单独确认。
4. 生成过程中重启实例，确认按已有任务 ID 恢复，未知提交状态进入核对，不自动重复调用或误退款。
5. PostgreSQL/Redis（若该部署启用）及 OSS/COS 的真实网络、权限和故障恢复；SQLite 测试不能代替 PostgreSQL 实测。
6. 真实服务器上的镜像构建/拉取、就绪探针、前后端 revision 一致性，以及使用备份恢复到隔离环境后的账号、积分与媒体核对。

前端构建仍有较大 chunk 的体积提示，性能分包优化不在本轮最小修复范围内。本项目不保证任意上游模型稳定或绝对无缺陷；“可有限试用”与“已完成公网生产验收”必须区分。
